TASK: shield__python_lattice_archive_traversal_001
CWE-22 Path Traversal via conditional validation bypass in storage gateway

ROOT CAUSE
==========

Lattice Archive implements path validation, but only conditionally. The
StorageGateway._resolve_path() method checks whether a requested file name
appears in the bundle's known_entries tuple:

    if requested_name in known_entries:
        candidate = bundle_root / requested_name
        return self._path_validator.safeguard(bundle_root, candidate)
    return bundle_root / requested_name

The safeguard() method properly resolves both paths and verifies containment
using relative_to(). However, this validation only executes when the file
name is in known_entries.

The vulnerability is in ArchiveService, which selectively passes known_entries:

    known = bundle.entries if "OPS" in code else ()
    return self._storage.preview_text(bundle.root_path, requested_name, known)

For non-OPS bundles (like "BX-APR-441"), an empty tuple is passed, meaning
the validation branch is never taken. User-controlled file names are joined
directly to the bundle root without any path containment check, enabling
traversal into sibling directories.

EXPLOIT
=======

Request:

    actor: workspace member (alma)
    code: BX-APR-441
    requested_name: ../../drafts/april-adjustments.csv

Flow:

1. The bundle access policy validates that alma can access BX-APR-441
   (same workspace). This check passes.
2. ArchiveService checks if "OPS" is in "BX-APR-441". It is not.
3. known_entries is set to an empty tuple ().
4. StorageGateway._resolve_path() receives known_entries=().
5. The condition `requested_name in known_entries` evaluates to False.
6. The method returns `bundle_root / requested_name` without validation.
7. The resulting path resolves to:
   data/workspaces/ws-finance-a/drafts/april-adjustments.csv
8. The file is read and returned to the user.

The same flow works for downloading bytes and for reaching files in
neighboring workspace exports or ops-restricted directories.

FIX
===

Remove the conditional validation and apply the safeguard to all paths:

    def _resolve_path(self, bundle_root: Path, requested_name: str, known_entries: tuple[str, ...]) -> Path:
        candidate = bundle_root / requested_name
        return self._path_validator.safeguard(bundle_root, candidate)

This ensures every path is resolved and verified to remain inside the
bundle directory, regardless of whether the file name appears in the
bundle's entry list.

WHY THIS IS HARDER
==================

1. The code contains a working path validator (PathValidator.safeguard),
   which may mislead agents into thinking validation is already in place.

2. The validation is gated by a conditional that appears intentional
   (optimization for known entries), making it look like a performance
   shortcut rather than a security flaw.

3. The ArchiveService uses a string matching heuristic ("OPS" in code)
   to decide whether to pass known_entries, which seems like a legitimate
   business rule for ops bundles.

4. The vulnerability requires tracing the flow across three layers:
   ArchiveService → StorageGateway._resolve_path → PathValidator.safeguard

5. The exploit does not use obvious patterns in the bundle code or
   file name that would trigger string-based detection.
